### API는 3년, 파일은 15년

07 과제가 5년을 요구하는데 API로 조회하니 2024·2025·2026 세 해뿐이었다.
2020~2023은 0건이라 처음엔 데이터가 없는 줄 알았다.

데이터셋 페이지를 뜯어 보니 공식 안내가 있었다.

> OpenAPI는 최근 3년 데이터부터 출력됩니다.

그 아래 **2011년부터 연도별 ZIP 파일**이 따로 올라와 있었다. 데이터가 없던 게 아니라
API만 제한이었다. `downloadFile(seq)` 함수와 `frmFile` 폼을 읽어 POST 요청을 재현했다.

```
POST https://datafile.seoul.go.kr/bigfile/iot/inf/nio_download.do
     infId=OA-21276&seq=<연도별 번호>&infSeq=3
     Referer 헤더 필요
```

| | API | 파일 |
| --- | --- | --- |
| 범위 | 3년 | 15년 (2011~2025) |
| 5년치 소요 | 약 4시간 | **34초** |

2021~2025년 323만 건을 받았다. 2011~2020년은 쓸 데가 없어 보류했다.
`scripts/fetch_seoul_rent_files.py`에 seq 번호가 다 있어 인자만 바꾸면 받는다.

### 파일 방식에서 걸린 것 셋

1. **ZIP 내부 파일명이 CP949** — `unzip`이 `Illegal byte sequence`로 죽는다.
   Python `zipfile`로 바이트를 직접 읽어야 한다.
2. **인코딩이 연도마다 다르다** — 2022년까지 CP949, 2023년부터 UTF-8(BOM).
   2019년 파일로 시험해 성공했다가 2023년에서 `UnicodeDecodeError`가 났다.
   BOM을 먼저 보고 판별하도록 고쳤다.
3. **열 이름이 한글** — 파일은 `자치구명`, API는 `CGG_NM`. 두 자료를 같이 쓰려면
   맞춰야 해서 API 쪽으로 통일했다. 건물명에 탭 문자(`\t(1-1)\t`)가 섞여 있어 정리했다.

### 분석에서 정정한 것 — 건수는 시장 규모가 아니다

5년치를 붙여 놓고 보니 신고 건수가 2021년 46만에서 2025년 102만으로 두 배 넘게
늘어 있었다. 시장이 커진 것처럼 보이지만, 월별로 그리니 **2025년 6월에 계단처럼**
뛴다. 2021년 6월 시작된 전월세신고제의 계도기간이 2025년 5월 말 끝난 시점이다.

건수는 시장 규모가 아니라 신고율의 변화다. 이걸 모르고 "5년간 거래가 2배 늘었다"고
쓰면 틀린 결론이 된다. 건수를 시계열에서 빼고 가격만 다뤘다. 표본 구성이 바뀐
구간이라 평균 대신 중앙값을 썼다.

접수연도 파일에는 과거 계약이 소급 신고된 건이 섞여 있다(2021년 파일에 2011년 계약 등,
전체의 1.85%). 시계열은 접수연도가 아니라 계약일 기준으로 잘라야 한다.

### 결과

아파트 ㎡당 환산전세가 2021-01 648만원 → 2025-12 729만원 (+12.5%).
자치구 격차는 2.15배 → 2.14배로 거의 그대로였다. 강남구 최고, 도봉구 최저가 5년 내내 같다.
건물용도별로는 단독다가구가 27.7%로 가장 많이 올랐고 연립다세대가 6.4%로 가장 적었다.

## 2026-09-14 — 서울 데이터 3종 확보와 폴더 정리

### 폴더 구조를 나눴다

데이터가 1.1GB로 불어나면서 최상위에 원본이 쌓이기 시작했다. 네 갈래로 나눴다.

| 폴더 | 성격 | git |
| --- | --- | --- |
| `data/raw/` | 내려받은 원본. 읽기만 한다 | 제외 |
| `data/interim/` | 중간 산출물. 다시 만들 수 있다 | 제외 |
| `data/processed/` | 분석에 바로 쓰는 결과 | 커밋 |
| `deploy/site/` | 웹에 공개되는 것 (기존 `public/`) | 커밋 |

`outputs/`(분석 결과)와 `deploy/site/`(공개물)를 나눈 이유는, 분석한 것을
전부 공개하지는 않기 때문이다. 공개할 것만 골라 옮긴다.

`wrangler.jsonc`는 지웠다. wrangler가 pages 배포 중 자동 생성하면서
`package.json`의 deploy 스크립트까지 Workers용(`wrangler deploy`)으로
덮어썼다. 이 프로젝트는 Pages를 CLI 인자로 배포하므로 설정 파일이 혼선만 준다.

### 서울 열린데이터광장 API

인증키는 **계정당 하나**다. 데이터셋마다 신청하는 게 아니라 키 하나로 전부 쓴다.
처음에 데이터셋별 신청이라고 잘못 안내했다.

두 데이터셋 모두 `INFO-000` 정상 응답 확인.

## 2026-09-14 — 자동 배포 구축

`main`에 push하면 GitHub Actions가 Cloudflare Pages로 배포한다. 워크플로는
`.github/workflows/deploy.yml`.

### 막혔던 지점과 해결

**Node 버전** — 기본 `node`가 conda 환경의 v20이라 wrangler(Node 22+ 요구)가 거부했다.
전역 PATH를 바꾸면 Claude Code 자체가 conda node로 돌아가고 있어 위험하므로,
프로젝트에서만 `/opt/homebrew/opt/node@22/bin`을 앞에 붙여 쓴다.

**Pages 프로젝트 생성** — 계정에 `workers.dev` 서브도메인이 없어 신규 Workers 통합
경로가 막혔다. `--force`로 기존 Pages 방식으로 생성했다. 이 플래그는 최초 1회만 필요하다.

**저장소 이름 충돌** — `smartcity`가 선점돼 있어 배포 주소는 `smartcity-apa.pages.dev`가 됐다.

**`workflow` 스코프** — `.github/workflows/` 파일은 `workflow` 스코프 없이 push할 수 없다.
`gh auth refresh -s workflow`로 추가. 이때 `gh`는 TTY가 없으면 'Press Enter' 프롬프트에서
멈추므로 `pty`로 띄워야 한다(`scripts/` 참고). wrangler는 브라우저를 자동으로 열지만
`gh`는 Enter를 먼저 기다린다는 차이가 있다.

**빈 시크릿** — `CLOUDFLARE_API_TOKEN`이 값 없이 등록돼 배포가 두 번 실패했다.
워크플로에 값 대신 길이만 출력하는 단계를 임시로 넣어 원인을 특정했다(길이 0).
GitHub 웹에서 다시 넣어 해결. 진단 단계는 제거했다.

### 최종 상태

- 배포 주소: https://smartcity-apa.pages.dev
- 저장소 시크릿: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`
- Cloudflare 계정: taecin.kim@snu.ac.kr (OAuth 토큰은 macOS 키체인)
- `workers.dev` 서브도메인: 미등록. 정적 페이지만 쓰면 불필요하다.

### 데이터를 다루며 지킨 원칙

  꺾은선으로 이으면 원자료에 없는 추세가 생긴다.
- 증감 색상은 피해 지표에만 적용한다. 강수량·면적은 좋고 나쁨이 없다.

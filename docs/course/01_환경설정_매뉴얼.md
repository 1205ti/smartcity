#### 1.1 Python (파이썬) 설치

PowerShell에서 Python을 실행해서 간단한 코드를 실행해 봅니다. 
- PowerShell은 명령어를 직접 입력해 컴퓨터를 조작하는 명령줄 환경입니다. 이처럼 검은 창에 글자 형태의 명령어를 입력해 컴퓨터를 조작하는 방식을 CLI(Command Line Interface)라고 합니다. CLI는 익숙해지면 컴퓨터 자원을 적게 사용하면서 빠르게 작업할 수 있고, 반복 작업을 자동화하기에도 좋습니다. 하지만 CLI에서 Python을 사용하면 코드를 작성하고 저장하거나 실행 결과를 확인하는 과정이 다소 불편할 수 있습니다. 그래서 프로그램을 개발할 때는 화면에서 파일과 메뉴 등을 쉽게 확인하고 조작할 수 있는 GUI(Graphical User Interface) 기반의 개발 도구를 많이 사용합니다.
- 최근에는 코드 작성부터 수정, 실행, 오류 확인까지 한곳에서 할 수 있는 통합 개발 환경(IDE, Integrated Development Environment)을 많이 사용합니다. IDE는 프로그래머가 소프트웨어를 보다 편리하게 개발할 수 있도록 여러 개발 도구를 하나의 작업 공간에 모아 둔 프로그램입니다. 최근에는 여기에 AI를 활용한 코드 작성·수정·설명 기능도 적극적으로 결합되고 있습니다. 이번 수업에서는 이러한 개발 환경으로 Visual Studio Code(VS Code)를 사용합니다. > 그런데 AI가 코드를 만들어 주는데 왜 Python을 배워야 할까요?
- 여기에서 Vibe Coding(바이브 코딩)이라는 개념이 중요합니다. 바이브 코딩은 사람이 코드를 한 줄씩 직접 작성하기보다, 자연어로 원하는 것을 AI에게 설명하고, AI가 코드를 만들도록 하는 개발 방식입니다. 실제로 2025년 연구에서는 바이브 코딩을 AI와 자연어로 대화하면서 프로그램을 만드는 새로운 프로그래밍 방식으로 설명하면서도, 프로그래밍 지식이 사라지는 것이 아니라 AI가 생성한 코드를 평가하고 수정하고 관리하는 능력으로 이동하고 있다고 분석합니다. 그래서 역설적으로 바이브 코딩 시대에는 Python을 완벽하게 외울 필요는 줄어들지만, Python을 이해해야 할 필요는 더 커집니다.
> 과거와 지금은 Python을 배우는 목적이 다릅니다
- 과거에는 프로그래밍 공부를 이렇게 생각했습니다.
문법 공부 → 문법 암기 → 직접 코드 작성 → 프로그램 완성
예를 들어 반복문을 만들려면 for, range, 들여쓰기 등의 사용법을 정확하게 기억해야 했습니다.
하지만 AI 시대에는 과정이 달라집니다.
하고 싶은 일 생각하기 → AI에게 설명하기 → AI가 코드 생성 → 실행 → 결과 확인 → 수정 요청
즉, 사람의 역할이 코드를 생산하는 사람에서 AI에게 일을 시키고 결과를 판단하는 사람으로 조금씩 이동하고 있습니다.
> 그렇다면 Python은 어느 정도까지 알아야 할까요?
바이브 코딩 시대의 초보자에게 중요한 것은 모든 문법을 암기하는 것이 아닙니다. 예를 들어 AI가 다음 코드를 만들어 주었다고 생각해 보겠습니다.
```Plain Text
import pandas as pd
df=pd.read_excel("survey.xlsx")
average=df["score"].mean()
print(average)
```
초보자가 이 코드를 처음부터 작성할 필요는 없습니다. 하지만 최소한,
- pandas가 데이터를 다루는 도구라는 것
- read_excel()이 Excel 파일을 읽는다는 것
- df라는 곳에 데이터가 들어간다는 것
- mean()이 평균을 구한다는 것
- print()가 결과를 화면에 보여준다는 것
정도는 이해할 수 있어야 합니다. 그래야 AI에게 “평균 말고 중앙값으로 바꿔줘.” 또는 “지역별 평균을 계산해서 막대그래프로 만들어줘.” 라고 더 정확하게 지시할 수 있습니다.
> AI가 있기 때문에 기초가 필요 없는 것이 아닙니다
- 2025년 Stack Overflow 조사에서는 개발자의 84%가 개발 과정에서 AI 도구를 사용하거나 사용할 계획이라고 답했습니다. 하지만 동시에 66%는 AI가 만들어 주는 답이 “거의 맞지만 완전히 맞지는 않는 것” 때문에 어려움을 겪는다고 답했고, 45%는 AI가 생성한 코드를 디버깅하는 데 시간이 더 걸린다고 답했습니다. 또한 AI 결과의 정확성을 신뢰한다는 개발자보다 불신한다는 개발자가 더 많았습니다.
- 따라서 앞으로 중요한 능력은 코드를 많이 외우는 능력보다는 AI가 만든 코드가 맞는지 판단하는 능력입니다. 그 판단을 하려면 최소한의 Python 지식이 필요합니다.
> 확장된 나의 능력 = 나의 기본 역량 × AI 활용 능력
- 핵심은 더하기(+)가 아니라 곱하기(×)라는 점입니다. AI가 아무리 뛰어나도 내가 문제를 이해하지 못하면 좋은 결과를 얻기 어렵고, 반대로 내가 가진 전문지식과 판단력이 높을수록 AI는 그 능력을 훨씬 크게 증폭시켜 줍니다.
- Python을 배우는 이유도 모든 코드를 직접 작성하기 위해서가 아니라, AI에게 더 정확하게 일을 시키고 AI가 만든 결과를 이해하고 검증하기 위해서입니다

#### 1.2 Git (깃) 설치
- 역할: 분산형 코드 버전 관리 시스템(Version Control System). 설치해 두면 VS Code, GitHub CLI, AI 코딩 도구에서도 프로젝트 변경 이력을 관리하는 데 활용할 수 있습니다.
- Git은 코드나 문서가 어떻게 바뀌었는지를 기록하고 관리하는 버전 관리 도구(Version Control System)입니다. 쉽게 말하면, Git은 작업할 때마다 “이 시점의 상태를 저장해 두는 타임머신”과 같습니다. 코드를 수정하다가 문제가 생기면 이전 상태로 돌아갈 수 있고, 어떤 부분을 누가 언제 바꿨는지도 확인할 수 있습니다. Git에서 가장 기본적인 흐름은 다음과 같습니다.
> 파일 수정 → 변경 내용 선택 → 저장(commit) → 필요하면 이전 버전 확인
- 여기서 commit(커밋)은 중요한 개념입니다. 커밋은 현재 작업 상태를 하나의 버전으로 저장하는 것입니다.
1. 공식 홈페이지(git-scm.com)에 접속하여 운영체제에 맞는 설치 프로그램을 다운로드합니다.

1. 기본 옵션 그대로 Next 버튼을 계속 눌러 설치를 완료합니다. PowerShell에서 아래와 같이 설치 확인을 합니다.
```Bash
git --version
```

#### 1.3 GitHub 계정 만들기
GitHub는 Git으로 관리하는 코드와 파일을 인터넷에 저장하고, 다른 사람과 공유·협업할 수 있게 해주는 온라인 개발 플랫폼입니다.
쉽게 말하면:
- Git = 내 컴퓨터에서 변경 이력을 관리하는 도구
- GitHub = Git으로 관리하는 프로젝트를 온라인에 올려 보관하고 공유하는 공간
예를 들어 Python 프로젝트를 Git으로 관리한 뒤 GitHub에 올리면, 다른 컴퓨터에서도 프로젝트를 내려받을 수 있고 팀원과 함께 코드를 수정할 수도 있습니다.
GitHub에서 가장 중요한 개념은 **Repository(저장소, Repo)**입니다. 저장소는 하나의 프로젝트를 보관하는 공간으로, Python 코드뿐 아니라 데이터 파일, 설명 문서, 이미지, 설정 파일 등 프로젝트에 필요한 여러 파일을 함께 관리할 수 있습니다.
GitHub를 사용하면 다음과 같은 일을 할 수 있습니다.
- 코드를 온라인에 백업하기
- 여러 컴퓨터에서 같은 프로젝트 작업하기
- 다른 사람과 코드 공유하기
- 팀원과 공동으로 프로젝트 개발하기
- 과거의 코드 변경 기록 확인하기
- 다른 사람이 만든 오픈소스 프로그램 살펴보기
- 자신의 프로젝트를 포트폴리오로 공개하기
Git과 GitHub의 관계
비유하면 이렇게 이해하기 쉽습니다.
> Git = 내 컴퓨터의 버전 관리 시스템
  GitHub = Git 프로젝트를 올려놓는 온라인 저장소
다만 GitHub는 단순한 파일 저장소보다 훨씬 강력합니다. 코드가 어떻게 바뀌었는지 추적하고, 여러 사람이 수정한 내용을 검토하고 합칠 수 있기 때문입니다.
AI·바이브 코딩 시대에 GitHub가 중요한 이유
AI에게 코드를 작성하거나 수정하게 하면 프로젝트의 변화 속도가 매우 빨라집니다. 이때 GitHub를 사용하면 AI가 만든 코드도 체계적으로 저장하고 관리할 수 있습니다.
또한 최근의 AI 코딩 도구들은 GitHub에 있는 프로젝트 구조와 코드를 읽고 작업하는 경우가 많습니다. 따라서 Git과 GitHub를 이해하면 AI에게 단순히 한 줄의 코드를 물어보는 수준을 넘어, 하나의 프로젝트 전체를 함께 개발하는 방식으로 발전할 수 있습니다.
그리고 AI 시대에는:
> GitHub는 사람과 사람뿐 아니라, 사람과 AI가 함께 소프트웨어를 만드는 작업 공간이 되고 있습니다.
1. GitHub 홈페이지(https://github.com/)에서 계정을 만듭니다.

#### 1.4 GitHub CLI (gh) 설치
GitHub CLI(Command Line Interface)는 웹 브라우저에서 GitHub 사이트를 열지 않고도 터미널에서 GitHub 기능을 사용할 수 있게 해주는 공식 명령줄 도구입니다. 명령어는 gh로 시작합니다.
Git 자체는 내 컴퓨터의 파일 변경 이력을 관리하는 도구이고, GitHub CLI는 내 컴퓨터의 Git 프로젝트와 GitHub 서비스를 터미널에서 쉽게 연결하고 제어하는 도구라고 이해하면 됩니다.
  왜 GitHub CLI가 필요한가요?
  - 터미널에서 GitHub 계정에 로그인할 수 있습니다. (gh auth login)
  - 웹사이트를 열지 않고 새 GitHub 저장소를 만들 수 있습니다. (gh repo create)
  - 현재 프로젝트를 GitHub 저장소와 연결하고 관리하는 작업을 간단하게 할 수 있습니다.
  - VS Code, Codex 같은 AI 코딩 도구가 터미널 명령을 통해 GitHub 작업을 자동화할 때 활용하기 좋습니다.
  - 이후 수업에서 코드 작성 → Git 저장 → GitHub 업로드 → Cloudflare 배포 과정을 연결할 때 편리합니다.
1. 공식 다운로드 페이지(cli.github.com)에서 installer를 다운로드하거나 터미널에서 아래 명령어로 설치합니다.
```Bash
# Windows (PowerShell)
winget install --id GitHub.cli
```

#### 2.2 새 리포지토리 생성

#### 3.2 ChatGPT Plugins 연결
Plugins(플러그인)이란?
ChatGPT의 Plugins(플러그인) 은 ChatGPT가 외부 서비스/도구와 연결되어 추가 기능을 사용할 수 있게 해주는 “확장 기능”입니다.  
예: 웹에서 정보를 찾아오거나, 파일/문서 서비스를 연결하거나, 특정 업무 도구의 기능을 ChatGPT 안에서 호출하는 방식입니다.
  주의: 수업/과제에서는 계정/개인정보 보호를 위해, 플러그인에 로그인할 때 비밀번호나 민감정보를 입력하지 않도록 안내하고, 필요한 경우에만 최소 권한으로 연결하세요.
연결 방법(기본 흐름)
1. ChatGPT 화면 왼쪽 하단의 설정(Settings) 또는 상단의 모델/도구 선택 메뉴로 이동합니다. (UI는 버전에 따라 약간 다를 수 있음)
1. Plugins / GPTs / Tools 관련 메뉴에서 플러그인(또는 커넥터)을 활성화(Enable) 합니다.
1. (플러그인 스토어/목록이 보이면) 원하는 플러그인을 Install(설치) 합니다.
1. 설치 후에는 채팅 화면에서 해당 플러그인을 선택하고, 필요 시 안내에 따라 로그인/권한 승인을 완료합니다.
1. 플러그인이 켜진 상태에서 자연어로 요청하면(예: “이 자료를 요약해줘”, “OO 서비스에서 데이터 가져와줘”) ChatGPT가 플러그인 기능을 함께 사용합니다.
1. GitHub와 Cloudeflare Plugin을 설치합니다.

#### 4.5 파이썬 일반 가상환경 (.venv) 생성 및 활성화
가상환경(venv)이 왜 필요한가?
Python 프로젝트마다 사용하는 라이브러리(예: pandas, geopandas, plotly) 버전이 다르면,
한 프로젝트에서 설치한 패키지가 다른 프로젝트를 망가뜨리거나(버전 충돌), 실행이 안 되는 문제가 자주 생깁니다.
가상환경(venv)은 프로젝트별로 독립된 Python 패키지 폴더를 만들어서 이런 문제를 줄여줍니다.
- 프로젝트별 패키지 분리: A 프로젝트에서 설치한 패키지가 B 프로젝트에 영향을 주지 않음
- 재현성(같은 환경) 확보: 다른 컴퓨터/팀원도 같은 패키지 버전으로 실행 가능
- 문제 해결이 쉬움: 꼬였을 때 .venv만 지우고 다시 만들면 정리 가능
  권장: 수업에서는 각 과제/프로젝트 폴더마다 .venv를 만들고, VS Code에서 해당 인터프리터를 선택해서 사용하세요.
1. IDE 터미널(Ctrl + `)에서 python -m venv .venv 명령어로 일반 가상환경을 생성합니다.
```Bash
# 가상환경 생성
python -m venv .venv

# .venv 활성화
.\.venv\Scripts\Activate.ps1
```

### 5단계: Cloudflare 배포 & 서브도메인 설정

#### 5.0 Cloudflare Pages vs Workers 비교 (언제 무엇을 쓰나?)
Cloudflare에는 배포 대상에 따라 대표적으로 Pages(프론트엔드/정적 사이트)와 Workers(서버리스 백엔드/API)가 있습니다. 둘 다 “엣지(Edge)에서 실행/서빙”된다는 공통점이 있지만, 목적과 세팅 방식이 다릅니다.
  | Cloudflare Pages | Cloudflare Workers | 구분 |
  | 정적 웹사이트/프론트엔드 배포에 최적 | API/백엔드 로직을 엣지에서 실행 | 한 줄 요약 |
  | HTML/CSS/JS, React/Vue/Svelte 등 프론트엔드, 문서 사이트, 포트폴리오 | REST API, 인증/권한, 프록시, 크롤링/가공, AI 호출 중계, 웹훅 처리 | 대표 용도 |
  | 빌드 결과물(정적 파일)을 CDN으로 서빙 | 요청이 올 때마다 JS/TS 코드가 실행되어 응답 생성 | 실행 형태 |
  | 기본은 정적(상태 없음) | 상태 없는 함수가 기본이지만, KV/D1/R2/Queues 등과 결합해 확장 가능 | 데이터/상태 |
  | 매우 간단(리포지토리 연결 → 자동 빌드/배포) | Wrangler 설정/배포가 중심(또는 대시보드) | GitHub 연동 |
  | https://프로젝트.pages.dev | https://이름.workers.dev (또는 커스텀 도메인) | URL 예시 |
  | 프론트엔드 결과물/대시보드/정적 페이지는 Pages로 빠르게 배포 | 외부 API를 감싸는 백엔드(키 숨기기, 요청 가공, CORS 해결 등)는 Workers | 수업에서의 추천 |
  빠른 선택 가이드:

  - “웹페이지(화면)를 올리고 싶다” → Pages

  - “API/서버 기능이 필요하다(키 숨기기, 데이터 가공, 인증 등)” → Workers

  - 둘 다 필요하다 → Pages(프론트) + Workers(백엔드) 조합

#### 5.1 Cloudflare Pages 배포
1. Cloudflare 대시보드(dash.cloudflare.com) 접속 ➔ Workers & Pages ➔ Create Application ➔ Pages ➔ Connect to Git 클릭
1. GitHub 계정 연결 및 리포지토리 선택
1. Project Name 지정 (입력한 이름이 https://[이름].pages.dev 주소가 됨)
1. Save and Deploy 클릭 ➔ 즉시 글로벌 배포 완료!

#### 5.2 Workers 기본 workers.dev 서브도메인 설정
1. Cloudflare 대시보드의 Workers 관련 설정에서 계정의 workers.dev 서브도메인을 확인하거나 변경합니다.
  이름.workers.dev와 사용자 소유 도메인(Custom Domain) 은 다른 개념입니다. 내 도메인(예: app.example.com)을 연결하려면 프로젝트의 Custom Domains/Routes 설정을 별도로 사용합니다.

#### 5.3 정적 웹 앱 파일 구성
- index.html : 구조 및 레이아웃
- styles.css : 테마 및 애니메이션 스타일

### 6단계: 작동 확인 — 간단한 앱 만들기
6.1 직접 앱 만들기
1. 메모장을 열어 “Hello World!”와 “본인이름”을 출력하는 index.html 파일을 만듭니다.
```HTML
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>Hello World</title>
</head>
<body>
  <h1>Hello World!</h1>
  <h3>Jae Seung Lee</h3>
</body>
</html>
```
  HTML 주석은 #이 아니라 <!-- 주석 --> 형식을 사용합니다. Cloudflare Pages는 정적 사이트의 기본 진입 파일로 보통 index.html을 제공합니다.
1. 텍스트에 컬러를 지정하도록 index.html를 수정합니다.
```HTML
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>Hello World</title>

  <style>
    h1 { color: red; }
    h3 { color: blue; }
  </style>
</head>

<body>
  <h1>Hello World!</h1>
  <h3>Jae Seung Lee</h3>
</body>
</html>
```
  간단한 실습에서는 <style>을 index.html의 <head> 안에 넣을 수 있습니다. 프로젝트가 커지면 styles.css 파일로 분리하는 것이 관리하기 쉽습니다.
1. 텍스트를 클릭하면 컬러가 변경되도록(동작) index.html를 수정합니다.
```Bash
# app.js : 동작 로직
# 일반적으로 별도 app.js을 생성하지만, 이번에는 index.html에서 동작 로직을 지정했습니다.

<html>
<body>
  <h1>Hello World!</h1>
  <h3>Jae Seung Lee</h3>
</body>

  <style>
    h1, h3 { color: black; cursor: pointer; }
  </style>

  <script>
    document.querySelector('h1').addEventListener('click', function () {
      this.style.color = 'red';
    });

    document.querySelector('h3').addEventListener('click', function () {
      this.style.color = 'blue';
    });
  </script>

</html>
```

### 💡 팁 & 자주 묻는 질문 (FAQ)
  Q. git push를 하고 난 후 웹사이트에 바로 반영되나요?
A. Cloudflare Pages와 GitHub가 연동되어 있다면 git push 후 자동 빌드·배포가 시작됩니다. 실제 배포 시간은 프로젝트 규모와 빌드 과정에 따라 달라질 수 있습니다.
  Q. 배포 후 페이지가 안 보여요.
A. 먼저 Cloudflare의 Deployment 상태가 성공(Success)인지 확인하세요. 성공인데도 이전 화면이 보이면 브라우저에서 Ctrl + Shift + R로 강제 새로고침해 보세요. 사용자 도메인을 연결한 경우에는 마지막으로 DNS 설정과 전파 상태를 확인하세요.
